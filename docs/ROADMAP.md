# 咯咯牧场迭代路线

> 状态：V0.5 内部版本已完成，等待小范围试玩反馈
> 下一步：收集外部试玩反馈，V0.6 再决定是否扩充内容或调整策略空间
> 核心目标：先把“养鸡、繁育、探索”做成一个有短期决策和中期追求的放置游戏，再公开给朋友测试。

## 1. 产品目标

咯咯牧场是一款面向手机浏览器的轻量放置游戏。玩家通过收取资源、孵化与繁育鸡只、配置探索队伍和升级牧场设施，逐步形成自己的鸡群与资源循环。

当前阶段优先验证三件事：

- 短期操作有选择：资源应投入孵化、繁育还是设施升级。
- 鸡只获得后有用途：生产、探索和繁育需要不同个体。
- 中期成长可感知：设施、鸡群和探索产出共同推动牧场进展。

项目暂不以大量堆叠鸡种、区域和任务作为主要目标。新增内容应先带来新的判断或搭配空间。

## 2. 核心循环

```text
鸡群放置生产
    -> 收取谷粒与羽毛
    -> 孵化或繁育鸡只
    -> 选择三鸡编队
    -> 探索获得蛋、零件和其他资源
    -> 升级设施并提高牧场能力
    -> 进入下一轮收集、培养和探索
```

设施负责提供长期资源消耗和稳定成长；鸡只负责提供收集目标、生产差异和队伍搭配；探索负责带回无法只靠放置生产获得的资源。

## 3. 迭代阶段

### V0.1 移动端玩法原型（已完成）

目标：确认养鸡、孵蛋、繁育和探索可以在单页移动端界面中组成可操作的基础原型。

- [x] 鸡舍放置生产与手动收取。
- [x] 普通蛋、闪光蛋孵化及公开概率。
- [x] 鸡只品种、词条、战力和基础繁育。
- [x] 三鸡编队与计时探索。
- [x] 浏览器本地存档和基础离线收益。
- [x] 移动端导航、反馈提示和 GitHub Pages 部署流程。

验收：玩家可以从初始鸡群出发，完成一次收取、孵化、编队和探索，并在刷新页面后保留进度。

### V0.2 牧场成长（已完成）

目标：为基础玩法补上资源消耗、阶段目标和可持续成长，让玩家不只是等待计时结束。

已实现范围：

- [x] 增加鸡舍、孵化器、繁育窝、仓库和训练场五类设施。
- [x] 设施升级消耗谷粒、羽毛和探索零件，最高为 `Lv.3`。
- [x] 设施分别影响鸡群容量、孵化速度、词条继承、离线储存和队伍战力。
- [x] 增加收取、孵蛋、繁育、组队、探索和设施升级任务。
- [x] 任务提供普通资源、零件、普通蛋和闪光蛋奖励。
- [x] 首页展示牧场等级、鸡舍容量、任务进度、设施等级和当前加成。

收尾范围：

- [x] 通过完整游玩流程检查设施成本、任务顺序和资源回流，避免出现明显停滞或无意义最优解。
- [x] 确认五类设施升级前后的效果在界面和实际计算中一致、可感知。
- [x] 补充探索完成后的稳定结果展示，避免玩家错过临时提示后无法确认产出。
- [x] 明确存档版本迁移和异常数据恢复方式，为后续数据结构扩展做准备。

可验证验收：

- 新存档可以不依赖调试操作完成收取、孵化、三鸡编队、两次探索、一次繁育和一次设施升级。
- 每种设施升级后，对应数值和实际玩法效果立即变化，刷新页面后仍然保留。
- 离开页面后重新进入，离线收益、孵化和探索状态能够正确恢复或结算。
- 任务只能领取一次，奖励到账后不会因刷新或重复点击再次发放。

验收结果：已用新存档完成六项牧场任务，实际升级五类设施并确认容量、孵化时间、词条继承、离线储存和队伍战力反馈；孵化与探索进行中刷新后均能继续并正确结算；探索结果在页面刷新后仍可查看；`320px` 视口无水平溢出。生产构建和类型检查通过。

本轮非目标：不扩充大量鸡种，不实现路线探索和正式战斗，不增加云端账户或多人功能。

### V0.3 鸡只与繁育（已完成）

目标：让获得哪只鸡、保留哪只鸡和如何选择亲本成为持续决策，而不只是追求更高稀有度。

计划范围：

- [x] 扩充到 8 个品种、12 个词条。
- [x] 增加工作能力和战斗定位，让同一品种的不同词条组合具有不同用途。
- [x] 增加词条锁定，在繁育时允许玩家保护重点遗传方向，并承担明确成本。
- [x] 增加突变线索，使特殊品种或词条的出现条件可以被逐步理解，而不是完全依赖盲抽。
- [x] 记录亲本谱系、代数和后代关系，并提供鸡只详情页查看。
- [x] 增加品种与词条图鉴，区分曾经获得和当前持有状态。
- [x] 增加基因粉尘：玩家在鸡群中手动选择具体鸡只并确认后进行转化。
- [x] 系统不得因为品种或词条重复而自动转化鸡只；编队、探索或繁育中的鸡只不能直接转化。

可验证验收：

- 同一品种的两只鸡可以因为词条和定位不同，分别成为更合适的生产、探索或繁育选择。
- 玩家能够查看一只繁育鸡的亲本与代数，并理解其主要词条来源。
- 锁定词条、普通继承和突变结果均有明确反馈。
- 鸡只转化必须由玩家主动选择并二次确认，取消操作不会改变鸡群或资源。
- 重复获得的鸡仍然完整进入鸡群，由玩家决定保留、编队、繁育或转化。

验收结果：已在 V3 旧存档迁移到 V4 后完成真实流程。图鉴正确记录 8 个品种、12 个词条的发现与当前持有状态；同品种鸡只会根据词条显示不同培养方向；手动转化支持选择、取消、二次确认、保护规则和刷新后持久化；锁定词条消耗基因粉尘并保证进入后代；新生鸡档案可查看亲本快照、代数、后代数和突变记录。`320px` 视口无水平溢出，生产构建与浏览器控制台检查通过。

本轮非目标：不实现完整路线探索、首领战、装备系统或自动批量转化。

### V0.4 探索与战斗

目标：把当前的单纯倒计时探索扩展成“移动 → 采集或战斗 → 继续移动”的自动节点循环，使队伍搭配和移动效率影响过程与产出，同时保持放置游戏的低操作负担。

过程模型：

```text
选择区域与编队
    -> 系统根据队伍能力与区域规则规划路线
    -> 移动到节点（按路径基础时间与移动速度计算）
    -> 处理采集、战斗或事件
    -> 自动前往下一节点
    -> 抵达首领或出口并结算整条路线
```

探索必须保存当前区域、队伍快照、阶段、目标节点、阶段起止时间、已访问节点、携带资源和过程记录。探索开始后不要求玩家途中操作，离线期间可以持续推进移动、节点处理和最终结算。

计划范围：

- [x] 建立 `moving`、`collecting`、`fighting` 三阶段探索状态机，替代整段单次倒计时。
- [x] 保留 3 个主题区域，为每个区域增加入口节点、自动规划的中段分支和收尾战斗。
- [x] 为节点之间设置独立移动时间，并预留队伍、装备、技能和临时 Buff 的移动速度修正接口。
- [x] 在探索界面展示当前阶段、节点路线、携带资源和过程记录，不要求途中确认。
- [x] 使用节点采集与自动战斗替代单次成功率结算；战斗结果必须显示战力差和成败原因。
- [x] 增加三地区自动事件池，每次探索触发一次且不要求玩家途中操作。
- [x] 增加首领特性，使不同区域的收尾战斗需要不同能力侧重。
- [x] 增加最小队伍体力状态，使移动、采集、战斗和失败产生可追踪消耗。
- [x] 增加一次性探索道具，并在用途明确后评估是否需要基础属性克制；当前首领特性和补给已经提供足够差异，暂不叠加属性克制。
- [x] 让鸡只的工作定位、战斗定位和词条影响采集效率、战斗评分、自动路线或事件收益。
- [x] 增加探索专属产出：首领胜利稳定带回设施图纸，稀有蛋保留概率产出；图纸用于 Lv.4 设施升级，不直接掉落已有手动转化来源的基因粉尘。
- [x] 展示探索过程和结算记录，使失败原因与队伍改进方向可理解。

首轮实现边界：

- 三个区域先使用固定的小型节点图，系统根据队伍战力自动选择稳妥采集路线或战斗近路，不实现无限随机地图。
- 移动、采集和战斗均使用短计时阶段；探索开始后自动推进到结算，不在途中等待玩家操作。
- “疾行”词条先作为移动速度来源，装备、技能和 Buff 仅保留标准化修正入口。
- 每次探索只自动触发一个区域事件，优势能力直接结算并展示，不增加选择按钮或弹窗。
- 战斗先使用队伍战力对节点威胁的自动结算，不在首轮引入生命值、回合技能或属性克制。
- 体力只影响采集效率和战斗评分，不导致探索中断；“沉着”“疾行”、守卫和支援提供疲劳抗性。
- 出发前可选择轻羽绑腿、耐力口粮或野外工具包，每次最多携带一种并在出发时消耗；探索途中不补充选择操作。
- 队伍、补给与区域事件统一产出移动速度、采集效率、疲劳减免和战斗评分修正，后续装备、技能或 Buff 复用同一接口。
- 普通节点奖励回流谷粒、羽毛、零件与蛋；首领胜利额外带回设施图纸，图纸只用于解锁 Lv.4 设施成长。

可验证验收：

- 探索过程中能够观察到至少两次移动和两次采集或战斗阶段，刷新页面后继续当前阶段。
- 移动阶段结束后自动进入节点处理，节点完成后自动继续移动，完整探索无需额外点击。
- 同一区域可以根据出发时的队伍配置采用不同路线，但路线变化不增加途中操作。
- 移动速度修正能够缩短路径时间，且不会改变采集或战斗阶段时间。
- 不同队伍配置在成功率、状态消耗或奖励类型上产生可观察差异。
- 区域事件会明确显示生效的词条或定位，以及由此获得的额外收益或移动加成。
- 收尾战斗会显示首领特性、克制能力、有效威胁、体力消耗和剩余体力。
- 玩家能够根据失败记录调整鸡只或道具后再次挑战。
- 探索专属资源能够回流到繁育或设施成长，而不是形成孤立货币。

本轮非目标：不实现玩家对战、实时操作战斗、无限随机地图或复杂装备养成。

目标：补齐首小时体验、长期目标和发布前稳定性，形成可以交给朋友持续试玩的版本。

- [x] 将牧场手册整理为六章顺序主线，覆盖收取、孵化、编队、探索、繁育与设施升级，并提供对应页面入口。
- [x] 增加图鉴总完成度、收集阶段、品种/词条分项进度和下一步发现建议。
- [x] 增加不依赖重复领取资源的长期成就，按累计收取、孵化、繁育、探索、设施升级和图鉴发现自动解锁。
- [x] 调整新手首小时节奏、设施成本、孵化速度和离线收益上限。
- [x] 完成移动端触控、窄屏布局、前后台切换和性能检查。
- [x] 建立显式存档迁移、异常恢复、JSON 导入导出、本地备份恢复和重置前备份流程。
- [x] 增加关键玩法逻辑测试和发布前冒烟流程。
- [x] 准备小范围试玩记录模板，明确区分功能缺陷、体验问题、数值反馈和后续内容建议；实际邀请在版本关闭后进行。

可验证验收：

- 新玩家不依赖开发者解释即可完成首轮生产、孵化、编队、探索和升级。
- 旧版本存档可以迁移；异常存档不会导致应用无法启动，并提供可理解的恢复方式。
- 手机浏览器前后台切换后不会重复计算或丢失离线收益和探索奖励。
- 测试反馈能够区分功能缺陷、体验问题和后续内容建议，并形成下一阶段候选项。

本轮非目标：不在小范围测试前引入社交、公会、排行榜、付费或长期运营系统。

## 4. 当前下一步

V0.3 已关闭。进入 V0.4 前先冻结探索过程的数据与决策边界，避免把事件、战斗、装备和无限地图同时引入。

V0.4 已关闭。探索定义与纯计算已拆分到独立领域模块，存档迁移和鸡只关键规则也已形成可测试边界；生产、繁育锁定、手动转化、图鉴、探索状态推进和存档迁移已纳入最小自动化测试。

V0.5 已先完成无服务器存档管理：日常进度继续自动保存在浏览器中，玩家可以导入导出 JSON 跨设备迁移；覆盖导入、恢复与重置均保留最近一份本地备份，主存档异常时会尝试自动恢复。
首小时目标已整理为六章顺序主线：早期收取与孵化门槛缩短，未解锁章节不提前领取，当前章节可直接前往对应玩法；旧存档沿用原领取状态，不重复发奖。图鉴已增加 20 项总完成度、阶段称号与下一发现方向，品种和词条仍保留各自明细。

长期成就和关键玩法测试已补齐。新存档首次收取即可完成主线第一章；数值收尾采用更平滑的设施升级倍率 `1.5`，普通/闪光/繁育孵化基准为 `6/9/11` 秒，仓库离线收益从 3 小时起步、每级增加 1.5 小时；同时完成 320px 窄屏、前后台切换、存档恢复和关键页面冒烟检查。

V0.5 的实现范围现已关闭；剩余的小范围朋友试玩属于外部反馈工作，不作为继续扩展本轮代码范围的前置条件。

## 5. 迭代原则

- 每一版只引入一组能改变玩家决策的系统，开始实现后不随意扩大范围。
- 优先补足成长目标和资源消耗，再扩充鸡种、区域和演出。
- 新资源必须有稳定来源和明确用途，避免只增加货币数量。
- 随机结果需要公开概率、可理解的影响因素或逐步揭示的线索。
- 涉及永久失去鸡只或资源的操作必须由玩家主动确认，不做自动转化。
- 存档结构变化必须提供迁移路径，不以重置玩家进度作为默认解决方式。
- 不以堆叠数量代替玩法深度；未达到当前版本验收标准的问题优先在本轮关闭。
